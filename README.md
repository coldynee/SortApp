# SortApp

Консольное приложение для работы с коллекцией объектов класса «Автобус»:
загрузка данных из файлов и из консоли, сортировка по трём полям, многопоточный поиск
вхождений и сохранение результатов в файлы форматов TXT, CSV и JSON.

Репозиторий: https://github.com/coldynee/SortApp

## Требования

- JDK 21
- Maven

Зависимости проекта:

- Jackson Databind — чтение и запись JSON;
- JUnit 5 — модульное тестирование.

## Сборка и тестирование

```bash
mvn clean test
mvn clean package
```

Точка входа приложения — класс `by.coldynee.Main`. После сборки приложение
запускается этим классом из среды разработки или из командной строки с
подключёнными зависимостями проекта.

## Использование

Программа работает в цикле. Переход между разделами выполняется выбором пункта
меню. Завершение работы доступно только через пункт `0` с подтверждением.
Некорректный ввод не завершает программу: значение запрашивается повторно.

| Пункт | Действие |
| --- | --- |
| 1 | Загрузка данных |
| 2 | Отображение текущих данных |
| 3 | Сортировка данных |
| 4 | Многопоточный поиск вхождений |
| 5 | Сохранение данных в файл |
| 6 | Очистка данных |
| 7 | Информация о программе |
| 0 | Выход |

### Загрузка данных

Доступные источники:

1. Ручной ввод.
2. Генерация случайных данных.
3. Файл TXT.
4. Файл CSV.
5. Файл JSON.

Для ручного ввода и генерации указывается количество объектов — целое число
больше нуля. При загрузке из файла значение `0` означает загрузку всех доступных
записей.

При ручном вводе команда `-1` на любом шаге прерывает заполнение и сохраняет
уже введённые объекты.

Если коллекция не пуста, перед загрузкой выбирается режим: дозаписывание к
существующим данным или перезапись коллекции. При неудачной загрузке
(отсутствующий файл, пустой файл, отмена ввода) исходная коллекция не изменяется.

### Отображение данных

Выводится не более 30 записей. При большем размере коллекции программа
предлагает показать полный список.

### Сортировка

Алгоритмы:

- пузырьковая сортировка;
- сортировка вставками;
- сортировка выбором.

Критерии:

- государственный номер;
- название модели (без учёта регистра);
- пробег;
- сортировка объектов с чётным пробегом.

В последнем случае объекты с чётным пробегом упорядочиваются по возрастанию
и размещаются на позициях, которые ранее занимали объекты с чётным пробегом.
Объекты с нечётным пробегом сохраняют свои исходные позиции и ссылки.

Все три алгоритма реализованы вручную. Сортировка выполняется непосредственно
в переданной коллекции.

### Поиск вхождений

Поиск выполняется в отдельном классе `MultithreadedCounter` и поддерживает
четыре режима:

1. По государственному номеру — полное совпадение без учёта регистра.
2. По модели — полное совпадение без учёта регистра.
3. По пробегу — точное совпадение строкового представления числа.
4. Универсальный поиск — частичное совпадение хотя бы в одном из трёх полей.

Каждый объект учитывается один раз, даже если условие выполняется для
нескольких его полей. Результат и время выполнения выводятся в консоль.

### Сохранение в файл

Поддерживаемые форматы: TXT, CSV, JSON. Режимы записи: перезапись файла и
добавление данных в конец существующего файла.

В качестве пути принимается имя файла или абсолютный путь. При отсутствии
расширения оно добавляется автоматически. Расширение одного из поддерживаемых
форматов, не соответствующее выбранному, заменяется на нужное.

Не принимаются пустые пути, пути, указывающие на каталог, имена, состоящие
только из расширения, и пути с несуществующим родительским каталогом.

## Модель данных и валидация

Класс `Bus` содержит три поля:

| Поле | Тип | Описание |
| --- | --- | --- |
| `stateBusNumber` | `String` | Государственный номер |
| `modelName` | `String` | Модель автобуса |
| `kilometrage` | `int` | Пробег в километрах |

Класс неизменяемый, создание объектов выполняется через `Bus.BusBuilder`.
Валидация вызывается при построении объекта, поэтому одинаковые правила
действуют для ручного ввода, генерации и загрузки из файлов.

Государственный номер:

- формат `А111АА77` или `А111АА777`;
- допустимые буквы: А, В, Е, К, М, Н, О, Р, С, Т, У, Х;
- цифровая часть номера — от 001 до 999;
- код региона — от 1 до 997;
- регистр приводится к верхнему, пробелы и дефисы удаляются.

Модель:

- непустая строка длиной не более 50 символов;
- допустимы буквы кириллицы и латиницы, цифры, пробелы, дефис и точка;
- первый символ должен быть буквой или цифрой.

Пробег:

- неотрицательное значение, не превышающее `Bus.MAX_KILOMETRAGE`.

Невалидная запись из файла пропускается с выводом сообщения о причине;
оставшаяся часть файла обрабатывается штатно.

## Форматы файлов

TXT — поля через точку с запятой, по одной записи на строку:

```text
А111АА77;Volvo;100000
```

Пустые строки и строки, начинающиеся с `#` или `/`, игнорируются.

CSV — поля через запятую:

```csv
ГосНомер,Модель,Пробег
А111АА77,Volvo,100000
```

При чтении первая строка пропускается, если она не содержит цифр (с целью пропуска строки заголовка).
При перезаписи заголовок добавляется автоматически, при дозаписи в
существующий файл — не дублируется.

JSON — массив объектов с полями `stateBusNumber`, `modelName`, `kilometrage`:

```json
[
  {
    "stateBusNumber": "А111АА77",
    "modelName": "Volvo",
    "kilometrage": 100000
  }
]
```

## Архитектура

| Пакет | Назначение |
| --- | --- |
| `by.coldynee` | Точка входа, консольное меню, ввод и обработка команд |
| `by.coldynee.model` | Класс `Bus`, строитель, константы и шаблон госномера |
| `by.coldynee.validation` | Правила валидации полей |
| `by.coldynee.collections` | Кастомная коллекция и многопоточный подсчёт |
| `by.coldynee.io` | Интерфейс источника данных, ручной и случайный ввод, генератор номеров |
| `by.coldynee.io.loaders` | Загрузчики TXT, CSV и JSON |
| `by.coldynee.io.output` | Интерфейс вывода и стратегии записи TXT, CSV и JSON |
| `by.coldynee.sorting` | Интерфейс сортировки, базовый класс, три алгоритма и компараторы |

Использованные паттерны:

- **Strategy** — независимое взаимозаменяемое подключение источников данных,
  алгоритмов сортировки и форматов вывода;
- **Builder** — пошаговое создание объекта `Bus` с валидацией перед созданием;
- **Template Method** — общая проверка входных данных и логика выборочной
  сортировки в базовом классе сортировок, конкретный алгоритм определяется
  в наследниках.

### Кастомная коллекция

`CustomArrayList<T>` реализует интерфейс `List<T>` и хранит элементы во
внутреннем массиве. Начальная вместимость — 2 элемента, увеличение — в два раза.
Для сдвига элементов используется `System.arraycopy`. При удалении и очистке
освободившиеся ячейки зануляются, чтобы не удерживать ссылки на объекты.

Сложность операций: добавление в конец — амортизированная O(1), вставка и
удаление по индексу — O(n), поиск по значению — O(n).

### Многопоточный подсчёт

`MultithreadedCounter.countOccurrences` принимает список и предикат, что делает
метод независимым от конкретного класса элементов.

Алгоритм:

1. Определяется число потоков по количеству доступных процессоров.
2. Список делится на чанки.
3. Каждый чанк обрабатывается задачей в `ExecutorService`.
4. Частичные результаты собираются через `Future<Long>` и суммируются.
5. Пул потоков закрывается в блоке `finally`.

Метод возвращает количество совпадений; вывод результата в консоль выполняет
слой командного меню. Коллекция во время работы метода не должна изменяться.

## Тестирование

Тесты написаны на JUnit 5 и вынесены в отдельный исход каталог тестов.
Используются параметризованные и повторяемые тесты, временные каталоги
(`@TempDir`) для файловых операций и условное пропускание проверок
устойчивости для алгоритмов, которые ей не обладают.

Проверяются, в частности:

- работа всех методов кастомной коллекции, включая итераторы, массовые
  операции, рост массива и выход за границы;
- корректность и эквивалентность трёх алгоритмов сортировки по всем трём полям,
  выборочная сортировка чётных значений, пустые и одноэлементные коллекции;
- загрузка валидных и повреждённых данных, пропуск битых записей, лимиты
  количества, отсутствующие файлы;
- запись и дозапись во все три формата, нормализация путей и расширений,
  обработка ошибок файловой системы;
- многопоточный подсчёт на пустых, одноэлементных и крупных коллекциях,
  работа с кастомной и стандартной реализацией `List`.

## Ограничения и допущения

- Алгоритмы сортировки имеют квадратичную сложность и не предназначены для
  больших объемов данных.
- Разбор CSV и TXT выполняется простым разделением по разделителю. Поддержка
  экранированных значений и кавычек не реализована; модель не должна содержать
  запятую или точку с запятой соответственно.
- Дозапись JSON реализована через манипуляцию строками: содержимое существующего
  файла должно быть корректным массивом, заканчивающимся на `]`. Иначе файл
  перезаписывается.
- `CustomArrayList.subList` возвращает копию диапазона, а не связанное с
  оригиналом представление. Это исключает влияние изменения чанка на исходный
  список при многопоточной обработке.
- Методы `contains`, `indexOf` и `remove(Object)` при аргументе `null`
  возвращают `false` или `-1`, независимо от наличия `null`-элементов в
  коллекции. Хранение `null` как значения при этом возможно.
- Итераторы коллекции не отслеживают структурные модификации исходного списка
  во время обхода. Поведение при такой модификации не определено.
- Коллекция не является потокобезопасной. Параллельно допускается только
  чтение без изменения структуры.
